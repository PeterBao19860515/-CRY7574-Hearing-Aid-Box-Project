# Standalone HTML program

Open `../CRY7574 Hearing Aid Box Measurement Manage Software.html` directly in a current Chrome or Edge browser. No Python server, network connection, account, installation or CDN is required.

Start in the **Data workspace**, which lists records across libraries. Click **Import files** and choose up to 100 Audio Precision XLSX or normalized XLSX/CSV/JSON files, choose a destination library and any tags, preview the files, then explicitly save the ready files. Files are processed sequentially. Each row shows success or an individual error; use **Retry failed saves** to retry failed records without saving successful files again. The app retains file handles and compact preview metadata rather than all batch file bytes in memory. Each file is read again when saving, and its preview hash must still match. Persistent operation IDs make a repeated save idempotent; reusing an operation with different bytes or options is rejected. Choosing files again starts a new intentional batch. Curves, original numeric values, metadata filters, project progress, source downloads and printable report snapshots run in the browser.

Data is saved in IndexedDB in the current browser, not written back into the HTML file. Moving or emailing the HTML does not move later imports or edits. Use **Export backup** and **Restore backup** to transfer or protect the complete browser workspace, including exact source bytes and report snapshots. Restore validates source hashes, IDs, record relationships, point arrays, task values and provenance before an atomic replacement; the current workspace remains unchanged after a rejected restore. Export your current backup before replacing a workspace. Clearing browser site data can remove saved records.

The app displays an explicit storage error if IndexedDB is unavailable or a write fails. It does not silently substitute temporary memory storage. Private browsing or restricted file access may limit persistence. Use a current Chrome/Edge browser with local storage permitted. XLSX decompression uses the browser's native `DecompressionStream('deflate-raw')`; unsupported browsers show a clear error.

Libraries are named user collections, separate from immutable source classification. Existing browser records and older version-1 backups migrate into **Alpair 5G reference** or **User imports** libraries without changing points, bytes or frozen reports. Create a custom library from the data page or import dialog, filter by library or tag, and select records to add/remove/replace tags or move them. A record belongs to one library and has up to 30 unique tags, each up to 50 characters; tags are trimmed and deduplicated without regard to case. Names of up to 100 libraries are unique without regard to case. The measurement list displays 50 records per page. Selection persists across pages but clears on filter changes, and records leaving the filtered scope during polling are deselected.

Imports retain the same 20 MB **per-file** limit (not per batch), 40 MB total uncompressed XLSX limit, 20 MB per archive entry and 1,000 entry limit. AP source units, numeric zeros, missing values and original row mappings remain intact. No additional smoothing, resampling, arithmetic unit conversion or pass/fail evaluation is performed. AP Summary entries are source metadata only. Existing reference measurements remain labeled Alpair 5G reference data, not CRY7574 validation.

Accepted new writes are bounded by 5,000 charts, 1,000 sources, 5,000 reports, 10,000 tasks, 100 libraries, 1,000 saved comparisons and a complete serialized backup size of 180 MiB. Every mutation checks these limits before its atomic commit. Browser quota may be smaller and is reported explicitly. Restore accepts validated older backups up to 200 MiB, including the earlier version-1 schema without libraries/tags; a restored legacy workspace above the current 180 MiB write policy remains readable/exportable, while additional writes are rejected. Export a backup before using a separate browser workspace for another collection. No capacity is claimed to be unlimited.

A Library is the highest-level classification, available as an optional Data filter. Browse and search immediately without opening a library. **Libraries** opens a compact manager for creation, viewing records and deletion. Example names such as Speaker Driver Tests, Complete Device Tests and Isolation Tests are suggestions, not automatically created categories. The default sort is **Recently imported**, based on recorded source import time, while actual test date is a distinct column and filter; unknown test dates remain unknown. Search covers titles, original source names, tags, test items and notes. Edit metadata on a single record without editing measurement values. **Tools** contains historical reports, project progress, the source archive and complete workspace backups.

Choose a Library filter to work within one collection, optionally refine by tags, then check individual records or **Select matching (N)** for every matching record across all filtered pages. The header checkbox selects only the current page. Bulk tags, export and plotting use the explicit selected count. Filtering clears selection. Select records and click **Plot selected**, or use a row's **View** action. A plot accepts up to 12 independent records and 32 total series with exactly matching display units. Mixed units are rejected without dropping the selection or converting values. Individual trace checkboxes show record, series and source identity. **Active record** chooses the original numeric table, metadata, source/CSV download and single-record report source. The table pages 50 or 100 original samples at a time using the global display precision, Missing values and exact AP/reference source-row mapping when available.

**Decimal places** is a single header setting: **Auto (original precision)** or a fixed 0–9 decimal places. It is saved in the current browser workspace, synchronized between tabs and included in backups; older backups without this setting use Auto. It controls mouse coordinates, each trace's nearest-sample values, numeric-table X/Y, plot axis labels and the four X/Y range input fields. Fixed settings retain trailing zeros and normalize negative zero. A nonzero value rounded to zero shows **≈0.00** (according to the chosen places); hover a displayed numeric value for its original precision. Auto retains full original numeric text for sample/table values and uses adaptive labels on axes. Clean resting range inputs show the chosen decimal places; Auto shows their original precision. Focus a clean field to edit its exact value, or hover it for the exact-range tooltip. Underlying plot bounds remain unrounded: Apply on untouched rounded fields preserves the exact range, even when a small positive X appears as 0.00 or a narrow range has identical rounded endpoints. Unapplied typed drafts remain unrounded and survive cursor redraws, refresh, precision changes, resizing and actions on the other axis. Apply, zoom, Auto Y and Reset replace drafts only for the affected axis. New report snapshots capture the current decimal setting for their displayed range labels; later global setting changes do not alter that report. Existing reports keep their original rendering. Source files, normalized JSON/CSV values and snapshot point arrays remain full precision.

**Export selected** creates either importable normalized JSON measurements or long-form CSV points for analysis. JSON exports are limited to 100 records and 20 MiB so they remain compatible with one-file reimport; select a smaller batch if necessary. Select the destination Library when importing JSON; blank import tags preserve exported record tags. This is not an AP workbook or a source-provenance backup: use **Original file** for exact supplied bytes, or **Export backup** for the complete workspace. **Export plot PNG** captures the displayed comparison and a source/series legend; it is an image, not numerical data. All three exports work offline.

Each curve in **Displayed traces** has **Color**, **Line style** and **Width** controls. Solid, dashed, dotted and dash-dot lines are supported. Changes save automatically in this browser, with a visible saved/error status and a retry path. Styles belong to each saved record and series, independently of overlay order or identical names in other records; closing and reopening the program restores them when those records are plotted again. Complete backups and normalized JSON measurement exports retain the styles. CSV exports retain numeric samples; PNG exports retain the displayed appearance and matching legend. New report snapshots capture saved styles; older reports without styles retain their original rendering. No samples, units, source files or annotations are rewritten by appearance changes.

The main Plot grid uses AP-inspired **major and auxiliary ticks**. X remains logarithmic: frequency decades receive stronger marks, useful intermediate frequencies receive secondary labels when space permits, and lighter minor lines subdivide each decade. Y remains linear, with aligned readable major values and minor subdivisions. Label visibility and density adapt to the current range, available screen width and numeric display precision. Narrow frequency zooms receive useful ticks while keeping their logarithmic projection. The graph frame and inward tick marks distinguish the axes from the grid. PNG export captures this current display; existing frozen reports retain their captured content. Reference: [Audio Precision APx500 User Manual v9.0.0](https://www.ap.com/fileadmin-ap/technical-library/APx500_User_Manual_v9-0-0.pdf?force=). This is a locally implemented visual convention, not official AP software integration.

The plot cursor distinguishes **Mouse X/Y** from every trace's **Sample X/Y**. Each trace independently selects its nearest original frequency by logarithmic distance, using the earlier original index on a tie (including repeated frequencies). Null samples read Missing and have no marker; numeric zero remains zero. Samples outside the visible view are labeled and do not create misleading markers. Cursor display uses original samples, with no interpolation or resampling. Pointer exit, view switches and range changes clear stale cursor readouts. Arrow keys inspect samples in the first enabled trace.

**Hide / Unhide** is reversible and works on one record or selected records. Normal views show visible records; choose **Hidden records** or **All records** to find hidden data. Hidden status is persisted metadata; original points and bytes do not change.

**Delete record**, **Delete selected** and **Delete library** are permanent operations. A confirmation dialog shows the exact name/count, hidden count, related frozen reports and original-source retention/removal counts. Enter the exact deletion password `CRYSOUND`, check the explicit confirmation and click **Delete permanently**. This built-in local password is a confirmation mechanism, not login authentication or secure access control. Passwords are never written into records, logs or backups; closing/canceling clears the form. Wrong passwords and incomplete confirmations do not change data. If records, hidden state or related reports change while a dialog is open, its scope becomes stale and deletion is rejected; close it and review again.

Deleting a library removes that library and all contained measurement records, including hidden records. Existing frozen reports remain intact. Original source bytes are pruned only when neither a surviving measurement nor any frozen report references them. Report cards provide original-source downloads even after their live measurement/library has been deleted. Backups preserve these valid historical snapshots without requiring their old chart or library to exist. Live records may never refer to a missing library/source. Built-in reference/default libraries can also be deleted; reloading does not recreate them. Zero libraries is valid and prompts creation of a new library before import. Restoring a backup can intentionally recover deleted data. Destructive operations can reduce validated legacy workspaces up to the prior 200 MiB restore limit, even while still above the current 180 MiB new-write policy.

Mouse chart view controls are local view changes only. Choose **Zoom axes → Both / X only / Y only**. Roll the wheel up to zoom in or down to zoom out around the pointer (logarithmic X, linear Y). Left-drag a rectangle to zoom into the chosen axes; drags smaller than six pixels in the selected dimensions are ignored. Press Escape to cancel a drag. Wheel movement outside the plot continues to scroll the page. Double-click inside the plot or click **Reset view** to restore the full source frequency range and Auto Y. **Auto Y** alone keeps the current X range and recalculates visible-series Y bounds. Numeric X/Y controls provide equivalent keyboard access, with Enter supported in the Y inputs; arrow keys on the chart still inspect original samples. Y limits can include zero and negative values.

X-only mouse zoom keeps the current visible Y extent fixed, including when it initially came from Auto Y. Y-only mouse zoom leaves X unchanged. Fixed Y ranges persist through series toggles, metadata polling and viewport resizing; choosing a new plot selection resets them. Supported view bounds are X 1e-9–1e15 Hz and Y ±1e15, with positive finite spans. The displayed points, numeric table, source bytes, metadata and report snapshots are unchanged by zooming. Zoom state is not written into the data backup.

The browser database is `CRY7574-Hearing-Aid-Box-Measurement-Manage-Software`, object store `workspace`, key `primary`. A bundled snapshot initializes it only if empty. A single IndexedDB read/write transaction serializes changes across open tabs; page refreshes do not overwrite existing browser data with the bundled seed. This local app has no authentication, cloud sharing or immutable audit system.

To build a clean public release from the project root, without private reference data or user measurements:

```sh
python3 portable/build_portable.py --empty --output "dist/CRY7574 Hearing Aid Box Measurement Manage Software.html"
```

The `--output` path is relative to the current directory unless absolute. This command leaves the main project-root HTML unchanged. The clean artifact starts a new browser workspace with one **Measurements** Library and no records, sources, tasks, reports, comparisons, environment media or specifications. Existing browser data is preserved when opening any build; a seed initializes only an empty database. Use a separate browser profile to inspect a clean release.

To rebuild the main project-root HTML with a separately supplied private snapshot, run:

```sh
python3 portable/build_portable.py
```

When `portable/seed.json` exists, this default command retains the previous private-seed behavior. When the file is absent, it builds an empty workspace automatically; a public checkout does not need private data to build. `--empty` always ignores an existing private snapshot. The default output is the main project-root HTML, so use the explicit `dist` output above for a clean release when preserving a local private artifact.

The build combines the clean workspace frontend, plot/display/axis helpers, specification engine and UI, reports/exports/comparisons/environment-media modules and browser backend into one HTML file. The previous layered frontend is preserved as source history but is not bundled. `seed.json` is a private read-only database export supplied separately and excluded from version control; rebuilding does not write to the original SQLite database. JSON/script terminators are escaped before embedding. No other files are needed to run the resulting HTML.


## Saved comparisons

**Save comparison** in Plot view creates a named, ordered set of linked records. The comparison has its own editable title, actual test date, tags and notes. **Saved comparisons** opens a searchable, paginated manager for opening, editing and password-confirmed deletion. **Add / remove records** changes the current plot; save the comparison to retain that membership, or use **Save as new** to create another comparison. Keep at most 12 records / 32 series with identical units; existing comparisons retain their captured unit. Comparisons are included in complete backups and older backups default to an empty list. They are separate from the supplied reference chart groups and never create new measurement samples.

Expand **Records in this plot** to view an original record's table, edit its saved metadata, remove it from this plot or open the original record's guarded deletion flow. Remove preserves its saved data. Deleting a comparison requires explicit confirmation and CRYSOUND and preserves all original records, source files and frozen reports. Original-record metadata edits appear wherever that record is used. Deleted source records remain explicitly marked as missing in comparisons, and hidden members are disclosed when opening. An incomplete comparison never claims to show unavailable data. Revision checks reject stale comparison edits/deletions; failed edits retain their draft, with Reload saved version and Save as new recovery options.

## Test environment photos and videos

Open a measurement with **View**, then scroll below the plot to **Test environment**. **Add photos / videos** selects multiple local files. Each file is decoded to verify that this browser can actually preview it, then saved to the active record captured when selection began. Successful items appear immediately; a failed item shows its own English error and **Retry** button. Adding media never changes original measurement arrays or source workbooks. No files are uploaded to an external service.

Photos show directly in a gallery; click a photo or **Enlarge** for the original-sized preview. Videos show their actual first frame and native inline playback controls, without autoplay. **Edit caption** saves a setup description of up to 2,000 characters. In a multi-record overlay, the gallery follows **Active record**, so each setup stays linked to its original measurement rather than to the comparison.

Supported files: JPG/JPEG, PNG, WebP and GIF (20 MiB per image); MP4, WebM, MOV and QT (50 MiB per video). Video codec support depends on the current browser; a supported filename alone does not guarantee playback. Files that cannot decode here are rejected before saving; re-encode unsupported video as a browser-playable MP4/H.264 or WebM. Source bytes remain unchanged, including image metadata and video encoding. Up to 12 items per record and 1,000 in a workspace, subject to the complete workspace's 180 MiB encoded backup limit and available browser storage.

QuickTime files downloaded from Feishu with a **.qt** extension are accepted alongside **.mov**. The app preserves the exact original filename and bytes and stores the canonical MIME type `video/quicktime`. For `.qt`, an empty or `application/octet-stream` OS file type, or a `video/mp4` file-type hint, is tolerated; the browser still has to decode an actual preview and the backend still requires the genuine QuickTime `ftyp` / `qt  ` signature. Merely renaming an MP4 or another file to `.qt` does not bypass that check. Original video playback remains controlled by the user, with no autoplay. Codec support depends on the browser; re-encode unsupported videos as MP4 (H.264) or WebM.

**Delete** on a media card requires explicit confirmation and the exact password `CRYSOUND`. It removes only that media item. Reviewed record/library deletion also includes its environment media and rejects a review made stale by another tab. Older app tabs cannot manage the new media; use the updated program for complete backups. If an older tab deletes a record without its media, the updated app exposes the preserved files under **Unlinked environment media** for preview or guarded deletion.

Environment originals are stored as separate local IndexedDB Blobs and lightweight metadata; normal polling does not read full videos. **Complete workspace backup** includes originals, captions and previews, and restore validates them before changing stored data. Older backups default to no environment media. Copying the HTML itself does not transfer browser data. Selected measurement JSON/CSV exports and frozen reports keep their existing measurement-only scope; use a complete workspace backup to transfer photos/videos. No real test-environment images or videos are bundled as examples.

### AP sheets with empty Y columns

An AP workbook may export frequency grids for sweeps with no measured Y values. The importer validates these recognized AP sheets, excludes them from measurement charts, and lists their worksheet names and reasons in the import preview. Other valid sheets still import. **Excluded worksheets** expands the detailed list; the complete original workbook remains available unchanged. A measurement with both numbers and missing Y points retains every original point, with missing values shown as missing rather than zero. An entirely empty-measurement workbook cannot be saved. Malformed nonempty cells still cause an explicit error. Repeated sweeps with identical AP measurement names use their worksheet names to distinguish displayed records; the exact AP title remains in source provenance.

## User specifications and limit overlays

Create a Library with **Purpose → Specifications / limits**, or open **Libraries** and choose **Use as specifications** for an existing Library. Import the user's actual specification curves into that Library using the normal Excel/CSV/JSON importer. Set the correct unit for normalized Excel/CSV; native AP source units remain authoritative. The Library purpose labels its records **Specification curve** without changing their source classification, original values or provenance.

Open **Specifications → New specification**. Choose a title, a specification Library, and an original record/series for **Lower limit**, **Upper limit**, or both. Frequency Response commonly uses both bounds; THD commonly uses an upper bound only, but the software does not invent thresholds or infer the intended direction. Limit grids must have unique ascending frequencies, valid measured values, matching units and at least one jointly covered frequency for two-sided specifications. Crossed bounds are rejected. The named definitions support create, search, edit and deletion with explicit confirmation and `CRYSOUND`; their original curve records remain saved. Hidden source curves are identified and remain usable through explicit profile selection. A missing/moved source or a Library converted to Measurements makes the definition unavailable rather than silently dropping one bound.

Plot measurement records, choose a saved **Specification**, then click **Apply specification**. Dashed teal lower / amber upper curves are explicitly labeled specifications; red markers identify out-of-limit original measurement points. Auto Y fits the visible measured points and applicable limits, including interpolated bounds at viewport edges. Manual Y remains user controlled. Applying limits does not change X bounds or any original measurement value. The active specification and its bounds are also identified in exported PNGs.

Below the graph, **Specification assessment** counts within-limit, out-of-limit, uncovered and missing original points for enabled measurement series. Counts include points outside the current zoom. **Live nearest original samples** follows the cursor with each trace's own sample frequency, measured value, lower/upper limits, status and positive exceedance in the original unit. Red rows distinguish above/below violations. **All out-of-limit original points** provides a paginated list; global decimal display settings apply without rounding the underlying comparisons. Specification records and series marked as reference lines are never assessed as measurements.

Interpolation uses linear Y between adjacent valid specification points in logarithmic frequency. Exact knots use their original values. Null gaps are never bridged and values outside coverage are not extrapolated. If either configured bound is unavailable at a sample, that sample is **Not evaluated**, even when the other bound is defined. Missing measured values remain **Missing measurement**. Equality to a bound is within limits; no extra tolerance is invented. A single-knot limit covers only that exact frequency.

Definitions and Library purposes persist locally and are included in complete backups; older backups default to ordinary Measurement Libraries and no specifications. Applying a definition is explicit for the current Plot view: a new plotted-record selection removes it, and changed/deleted definitions or changed Library classification require review/reapplication. Saved comparisons continue to link their original measurements and do not automatically choose a specification. Existing frozen reports keep their captured measurement-only scope; Plot assessments are user-specification comparisons, not formal chamber validation certificates. Deleting a specification Library removes its definitions after reviewed-scope password confirmation; deleting one underlying curve retains affected definitions as unavailable. Original source bytes still needed by surviving records or frozen reports remain saved.

## SPL unit spelling when applying specifications

When applying a saved specification to measurements, the exact spellings **dB SPL**, **dBSPL** and **dB(SPL)** are accepted as equivalent SPL labels. No values are converted and original record/specification units, samples, source bytes and backups remain unchanged. Other units must match exactly; a mismatch shows both sides. This compatibility applies only at specification application: ordinary multi-record plots and the lower/upper sources used to define a specification still require identical unit strings. It does not equate dB, dBV, dBFS, Vrms, %, arbitrary capitalization or dBSPL1 (whose existing AP import label handling is separate).

## Schedule workspace

Click **Schedule** in the primary navigation, immediately after **Data workspace** and **Plot view**, to manage tasks independently. The older **More tools → Project progress** entry also opens Schedule. Tasks, owners, optional start/due dates, status, completion and notes are stored in the same `tasks` collection used by earlier versions. New tasks start without an assigned owner or invented dates; enter an owner explicitly. Search task titles, owners or notes and filter by status or **Overdue**. Task cards show the title, owner, start/due dates, status, completion bar and notes, with Edit/Delete actions. Up to 50 matching cards are shown per page, latest changes first. Overall counts and weighted completion remain explicit above the cards. **Table view · current page** retains the compact table as a secondary disclosure; it shares filters and pagination with the cards. Creating a task clears task filters so its saved row is visible. Due dates before the current local calendar date are marked overdue unless the task is Complete; due today is not overdue.

**Gantt view · current page** shows only that page's tasks that have both recorded dates. Bars use the inclusive start-to-due range; undated tasks are counted as omitted. Its SVG has at most 50 task rows and five date marks, with no daily-cell expansion even for long date ranges. Edit task metadata and completion from a card or the secondary table. Planned requires 0% and Complete requires 100%; selecting those statuses fills the corresponding percentage. Overall recorded completion uses task weights; the default is 1 and custom weight is under **Advanced**.

Edits carry a reviewed task revision so another current app tab cannot be silently overwritten. Failed edits retain the form draft; after a stale edit, close and reopen to review the saved version. **Delete** removes only the reviewed task after explicit confirmation and the exact password `CRYSOUND`; stale revisions, wrong passwords or canceling leave the task unchanged. Passwords are not saved. Older tasks/backups without `startDate` or `revision` migrate to an unknown start date and revision 1. Backups validate calendar dates and start/due order before replacement. Legacy API edits without an expected revision remain accepted for compatibility; the current UI always sends its revision. This scheduler does not change measurements, source files, media or frozen reports.

## Optional Codex MCP connection

The standalone workspace remains usable offline. To let Codex operate the **currently open browser workspace**, start the optional local MCP service following [the MCP setup guide](../mcp/README.md). Open **More tools → Codex MCP**, choose its generated connection JSON file, then click **Connect**. Selecting a file alone opens no connection. Only an explicit `http://127.0.0.1:<port>` address is accepted. Allow local-network access if the browser asks. Closing the panel keeps the connection running; reopen it to **Disconnect**. Reloading requires choosing the connection file and connecting again.

The connection token lives only in this page's memory: it is not stored in IndexedDB, session storage, tasks, logs or complete backups. A small connection indicator remains visible while connected. The bridge exposes a fixed operation list, not arbitrary JavaScript or arbitrary API calls. Codex can read paginated record points/metadata, libraries, tasks and specifications; import local measurement files; create libraries; edit record metadata/tasks; and open Plot or Schedule. Original measurement values remain immutable. Original-source downloads, environment-media bytes, complete-backup export/restore and arbitrary scripts are outside the MCP operation list.

A Codex deletion request **only opens the existing task, record or library review dialog** and reports that confirmation is required. You must type the deletion password and confirm in this browser. The bridge never accepts a password argument or reports a deletion before that separate browser action. Existing open edit/import/confirmation dialogs block destructive requests instead of being replaced. The same reviewed scopes, task revisions, immutable-source rules and complete workspace storage continue to apply; the MCP service does not create another data database.

## Release versions

The first formal product release is **V1.0.1**. `VERSION` holds the shared numeric `major.minor.patch`; the standalone builder validates it and embeds it in the visible header/footer and `app-version` metadata. Building does not increment it. Each subsequent authorized release push increments the patch (V1.0.2, V1.0.3, …) through the release workflow, rebuilds the empty distribution and preserves private data exclusions. Product version changes do not change the workspace/backup schema or stored measurements. MCP summaries report the actual open browser page version separately from the local server version; reopen the updated HTML to use the new frontend.
